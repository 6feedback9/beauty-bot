# 🤍 Beauty Guide — бот подписки (с оплатой WayForPay)

Девочка заходит → читает о Beauty Guide и FAQ → оплачивает подписку
картой через WayForPay → бот выдаёт ссылку в закрытый канал →
через 30 дней доступ закрывается автоматически.

Подписки хранятся в базе PostgreSQL — данные не теряются при
перезапусках Render.

---

## ЧАСТЬ 1. База данных PostgreSQL на Render

1. На Render: **New +** → **PostgreSQL**.
2. Name: `beauty-db`. Region — тот же, что у бота. Plan: **Free**.
3. **Create Database**. Подожди, пока статус станет «Available».
4. На странице базы найди **Internal Database URL** — длинная строка
   вида `postgresql://...`. Скопируй её.
5. Эта строка пойдёт в переменную `DATABASE_URL` бота (см. часть 4).

> Бесплатная база Render живёт 30 дней, потом её нужно пересоздать
> или перейти на платный план (~$7/мес). Для постоянной работы —
> платный план.

---

## ЧАСТЬ 2. Настройка WayForPay (делает заказчица)

В личном кабинете WayForPay:

1. Убедиться, что магазин **активирован**.
2. Взять **merchantAccount** (логин мерчанта, напр. `beautyguidetati_com`).
3. Взять / **перевыпустить secretKey** (секретный ключ).
4. Узнать, какой **домен** привязан к мерчанту — он понадобится для
   переменной `WFP_DOMAIN` (напр. `beautyguidetati.com`).

> ⚠️ Секретный ключ — это пароль. Не передавать в переписке, чатах,
> скриншотах. Вписывается только в переменные Render напрямую.

---

## ЧАСТЬ 3. Канал и бот (если ещё не сделано)

- Закрытый канал создан, бот в нём **администратор** с правами
  «Добавление подписчиков» и «Блокировка пользователей».
- Бот создан в @BotFather, токен на руках.
- ID канала известен (через @getidsbot, с минусом).

---

## ЧАСТЬ 4. Переменные окружения на Render

Сервис бота → **Environment**. Должны быть такие переменные:

| Key             | Value                                            |
|-----------------|--------------------------------------------------|
| `BOT_TOKEN`     | токен от BotFather                               |
| `ADMIN_ID`      | ID заказчицы (чтобы ей шли уведомления)          |
| `CHANNEL_ID`    | ID закрытого канала (с минусом)                  |
| `WEBHOOK_HOST`  | адрес сервиса, напр. `https://...onrender.com`   |
| `PYTHON_VERSION`| `3.12.7`                                         |
| `DATABASE_URL`  | Internal Database URL из части 1                 |
| `WFP_MERCHANT`  | merchantAccount из WayForPay                     |
| `WFP_SECRET`    | секретный ключ WayForPay                         |
| `WFP_DOMAIN`    | домен, привязанный в кабинете WayForPay          |
| `SUB_PRICE`     | цена подписки в грн, напр. `699`                 |
| `SUB_DAYS`      | срок подписки, `30`                              |

## ЧАСТЬ 5. Залить код и запустить

1. Залить на GitHub: `bot.py`, `requirements.txt`, `README.md`.
2. Render сам пересоберёт сервис.
3. В логах дождаться: `База данных готова` и `Бот запущен`.

---

## ЧАСТЬ 6. Тест оплаты — ОБЯЗАТЕЛЬНО на тестовых картах

WayForPay даёт тестовые реквизиты карт (см. их документацию,
раздел «Тестові реквізити»). Перед приёмом реальных денег нужно:

1. Оформить подписку в боте, оплатить **тестовой картой**.
2. Проверить, что после оплаты бот прислал ссылку на канал.
3. Если оплата не проходит — смотреть логи Render: там будет
   ответ WayForPay (частая причина — несовпадение домена
   `WFP_DOMAIN` с тем, что привязан в кабинете, или подпись).

Только когда тестовая оплата прошла полный круг (оплата → доступ
в канал) — можно принимать реальные платежи.

---

## Как работает оплата (для понимания)

1. Девочка жмёт «Оформить подписку».
2. Бот создаёт счёт в WayForPay, получает ссылку на оплату.
3. Девочка оплачивает картой на странице WayForPay.
4. WayForPay присылает боту подтверждение на адрес
   `/wayforpay-callback`.
5. Бот проверяет подпись, и если оплата успешна — выдаёт доступ
   в канал и записывает подписку в базу.

---

## Если что-то не работает

- Бот не отвечает → проверить webhook (логи Render: `Бот запущен`).
- Счёт не создаётся → логи покажут ответ WayForPay; чаще всего
  дело в `WFP_DOMAIN` или ключе.
- Оплата прошла, доступа нет → проверить, что `serviceUrl`
  доходит до бота, и подпись callback сходится (логи).
